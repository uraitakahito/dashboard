画面は 4 つの面からなります。
上のタブで切り替え、URL の `#` が面を決めます（`#crawls`・`#archives`・`#scripts`）。
中身の面のタブは、アーカイブの行の「開く」で入るまで出ません。

| 面 | 何が並ぶか |
| --- | --- |
| クロール | 1 行 = 1 本。状態・撮れた数・見つけた数・WACZ（撮ったページを 1 つの ZIP にまとめたアーカイブ）の数・かかった時間・run への行き先。上の欄から起こせる |
| アーカイブ | 見えている WACZ。行から検証・中身・[replay](https://github.com/uraitakahito/replay)（WACZ をブラウザで再生する画面）へ |
| 目録 | ページの中で走らせるスクリプト。空なら赤で言う |
| 中身 | WACZ 1 本の中。[WACZ を見る](/wacz/)に書いた |

画面の上には、誰として見ているかが出ます（「… として見ています —— 開発用の名乗りです」）。
足元には、いま並んでいる行の数と、次に引くまでの間隔が出ます。

## 並ぶのは台帳の 1 ページ

クロールとアーカイブは、台帳が返す最初の 1 ページ（新しい順）だけを並べます。
画面は続きを取りに行きません。
アーカイブは、そのページの中から名乗りが見てよいものだけが返るので、1 ページの数より少ないことがあります。
足元の「クロール N 本 ／ アーカイブ N 本」は並んでいる行の数で、台帳に在る全部の数ではありません。

## クロール

1 行が 1 本のクロールです。
状態・id の先頭 8 文字・起こした人と組織・最初の起点の URL・撮れた数・見つけた数・WACZ の数・かかった時間が並び、右端の「run ↗」が Windmill の run を新しいタブで開きます。

- **撮れた数と見つけた数は、欄を分けてある。**
  見つけた数（`pagesDiscovered`）はリンクを辿って見つけた数なので、深さ 0 のクロールは「撮れた 1・見つけた 0」になります。
  1 つの欄に `1 / 0` と並べると、分母より分子が大きく見えてつまずきます。
- **かかった時間は、走行中なら「いままで」。**
  終わった時刻が無いのは「まだ終わっていない」であって、「時間が無い」ではありません。
- **run ↗ は、最後に投げた段の run。**
  行き先は、台帳が返す `lastJob` の id と、サーバが `/healthz` で配る Windmill の origin と workspace から組みます。
  台帳が `lastJob` を持たない行には出ません。
- **行を押すと、失敗の文・走らせたもの・取れなかった URL が出る。**
  そのときだけ `/api/crawls/:id` を引きます。
  先頭は台帳の `error` で、文は言い換えません。
  compile の段で落ちたクロールは 1 枚も撮っていないので、取れなかったページが空になり、それだけでは成功のように読めるためです。
  次が走らせたもので、並びが実行順です。
  目録の物は版を、その場で書いた物は「その場」と出し、その場の物には「欄に戻す」が付きます。
  最後が取れなかったページで、並ぶのは台帳が返す分だけです。
  1 つも無ければ、そう言って起点の URL を並べます。
- **開いた行は、引き直しても閉じない。**
  表は引くたびに作り直すので、開いている行を id で覚えておき、最後の答えで開き直します。
  引き直すのは、走行中か、状態が変わった行だけです。

### 上の欄から起こす

表の上の欄から、クロールを起こせます。
起点の URL を 1 行に 1 本書き、「このページだけ」か「リンクを辿る（台帳の既定）」を選んで「起こす」を押します。
「走らせるもの」では、目録のどれを走らせるかを選び、その場で書いた JS を足せます。

- **送るのは、起点の URL と、深さ 0 かどうかと、走らせるもの（既定から変えたときだけ）。**
  「このページだけ」は `maxDepth: 0` を送り、「リンクを辿る」は何も足しません（深さも枚数も台帳の既定）。
  目録を全部選んだままで、その場の JS も無ければ、`scripts` は送りません。台帳の既定が走り、目録が空なら今までどおり 400 です。
  そうでなければ `scripts` を送ります。その場の JS が先、選んだ目録が目録の並びで後です。全部外せば `[]` で、何も走らせません。
  URL も JS の名前も画面では検査せず、台帳が 400 で言います（断った id を名指します）。
- **その場の JS は、strict の TypeScript として型を検査されます。**
  最初の段の compile で検査され、1 つでも誤りがあればクロールごと落ちます。診断は行を開くと読めます。
  IIFE で包み、取り出す要素には型を付けて `?.` で扱ってください。型の検査を外すなら、1 行目に `// @ts-nocheck` です。
  `export` は書かないでください。ページで構文エラーになり、何も走りません。
  「読み込みの後」は主フレームで 1 回、「遷移の前」は全部のフレームで遷移のたびに走り、受け皿（`__bh`）がありません。
  「ファイルを読む」は、別の所で書いたファイルを欄に読み込みます（ブラウザの中だけで読みます）。
- **202 の後、起点の URL は消え、その場の JS は残る。**
  直して撮り直すことが多いからです。
- **答えは、欄の下に 1 行で出る。**
  受理されたら、その行に印が付きます（走行中なので、足元は 2 秒ごとに引くようになります）。
  走行中のクロールがあれば 409 で、塞いでいる行に印が付きます（台帳は全体で 1 本しか走らせません）。
  それ以外は、台帳の文をそのまま出します。
- **起こした行は開かずに、印を付ける。**
  印は id で覚えておき、描き直しのたびに付け直します。

送る道は、[中継の口](/routes/)の `POST /api/crawls` です。

### 状態は stopReason と合わせて言う

`state` だけでは足りません。
`succeeded` には、全部を辿り終えた完走と、深さや枚数の上限で止めた打ち切りが混ざっています。
画面は `stopReason` と合わせて「完走」「打ち切り (深さ)」のように言い分け、知らない `stopReason` は括弧に入れてそのまま見せます。

言い分けの規則は `public/format.js` の `stateOf` で、`test/format.test.mjs` が固定しています。
ブラウザが読むのと同じファイルを試験も読むので、写しが腐りません。

## アーカイブ

見えている WACZ が、撮った時刻の新しい順に並びます。

- **「完全か」の `—` は「分からない」。**
  台帳の `waczComplete` が null の行で、「欠けあり」とは別です。
- **「検証」は、押したときだけ走る。**
  一覧を開くだけでは走りません。
  結果は行の「仕様どおりか」にも残るので、何本か見た後でも、押し直さずに思い出せます。
  報告に何が出るかは [WACZ を見る](/wacz/)に書きました。
- **「開く」で中身の面に入る**（`#wacz/<archiveId>`）。
- **「replay ↗」は replay で開く。**
  行き先は、サーバが `/healthz` で配る replay の origin と、台帳が返す `objectKey` から組みます。

## 目録

撮るページの中で走らせるスクリプトの一覧です。
id・版・ページのどの時点で走るか（`phase`）・sha256 の先頭が並びます。
同じ一覧が、クロールの面の欄の「走らせるもの」に、チェックとして並びます。

**目録が空なら、赤で言います。**
撮影のサーバ（BrowserHive）は走らせるものを自分では持たないので、目録が空だとページの中で何も走りません。
スクロールも遅延読み込みも起きないまま、それでも取り込みは成功し、アーカイブも出ます。
赤い文の中に、[capture-ledger](https://github.com/uraitakahito/capture-ledger)（クロールを起こし、撮れたものを記録する台帳）で取り込むコマンドが出ます。

## 引く間隔

走行中のクロールが 1 本でもあれば 2 秒ごと、無ければ 30 秒ごとに、一覧を引き直します。
写しを持たなくても、走っている間は live に見えます。
動いていないときは黙ります。

取りに行けなかったときは、最後に描けた表を残したまま、画面の上に理由を出します（[クイックスタート](/quickstart/)の「出た文から直す」）。
